# FTA — Football Tactics Architect

선수를 직접 배치하고 경기 계획을 완성하는 웹 기반 축구 전술 보드입니다. 현재 단계는 공모전 핵심 인터랙션을 검증하기 위한 로컬 프로토타입이며, 모든 선수 이름과 능력치는 가상 데이터입니다.

## 현재 구현

- `4-3-3`, `4-2-3-1`, `3-4-2-1`, `4-4-2` 포메이션 전환
- 마우스와 터치를 함께 지원하는 Pointer Events 기반 선수 드래그
- 선수 선택 후 경기장 탭 이동과 방향키 이동
- 선발 선수 선택 후 교체 명단 투입
- 경기 성향, 공격 폭, 수비 라인, 압박 강도 설정
- 선수 배치에 따라 변하는 전술 폭, 라인, 균형도 피드백
- 최근 10단계 선수 배치 되돌리기와 기본 배치 초기화
- 완성된 경기 계획을 확인하는 전술 카드
- 데스크톱, 태블릿, 모바일 반응형 레이아웃

## 조작 방법

1. 포메이션과 경기 지시를 선택합니다.
2. 경기장 위 선수를 원하는 위치로 드래그합니다.
3. 모바일에서는 선수를 선택하고 경기장 빈 공간을 눌러 이동할 수 있습니다.
4. 키보드 사용자는 선수에 포커스한 뒤 방향키로 이동합니다. `Shift + 방향키`는 더 큰 간격으로 이동합니다.
5. 필드 선수를 선택하고 교체 명단의 선수를 누르면 같은 위치로 교체 투입됩니다.
6. `전술 카드 완성`을 눌러 최종 경기 계획을 확인합니다.

## 기술 구성

- React 19
- TypeScript 5
- Next.js 호환 `vinext` 런타임
- Vite 8
- Cloudflare Worker 호환 빌드
- 별도 드래그앤드롭 라이브러리 없이 Pointer Events 사용
- 인증, 유료 API, 외부 데이터 키 미사용

## 선수 데이터

2026 FIFA 월드컵 선수 명단, PlayerElo 및 시뮬레이션용 세부 능력치 데이터베이스의 구조·생성·검증 방법은 [`data/README.md`](data/README.md)를 참고합니다.

## 프로젝트 구조

```text
app/
├── TacticsBoard.tsx      # 전술 보드 UI와 상호작용
├── tactics-data.ts       # 목업 선수 및 포메이션 데이터
├── globals.css           # 반응형 디자인 시스템과 경기장 표현
├── layout.tsx            # 공통 메타데이터와 문서 구조
└── page.tsx              # 서비스 진입 화면
lib/
└── tactics-core.js       # 좌표 제한, 포메이션 배치, 전술 형태 계산
tests/
├── tactics-core.test.mjs # 순수 전술 로직 테스트
└── rendered-html.test.mjs # 빌드 산출물 및 접근성 smoke 테스트
```

## 로컬 실행

### 요구사항

- Node.js `>=22.13.0`
- npm

### 설치 및 실행

```bash
npm install
npm run dev
```

개발 서버가 시작되면 [http://localhost:3000](http://localhost:3000)에서 확인할 수 있습니다.

## 검증

```bash
npm run lint
npm run typecheck
npm test
```

전체 검증은 다음 명령으로 한 번에 실행합니다.

```bash
npm run verify
```

## 데이터 확장 방향

현재 `app/tactics-data.ts`의 목업 데이터는 UI와 분리되어 있습니다. 실제 월드컵 데이터 도입 시 선수 데이터 공급 계층만 교체하고, 정규화된 `0...100` 경기장 좌표와 전술 보드 인터랙션은 그대로 유지할 수 있습니다. 실제 데이터 전환 전에는 사용 출처, 라이선스, 갱신 시점과 장애 시 fallback 정책을 먼저 확정해야 합니다.

## Git 전략

### 태그 컨벤션

- `init`: 가장 처음 Initial Commit에 태그를 붙일 때 사용합니다.
- `feat`: 새로운 기능을 구현할 때 사용합니다.
- `fix`: 버그나 오류를 해결할 때 사용합니다.
- `docs`: README, 템플릿 등 프로젝트 내 문서를 수정할 때 사용합니다.
- `setting`: 프로젝트 관련 설정을 변경할 때 사용합니다.
- `add`: 사진 등 에셋이나 라이브러리를 추가할 때 사용합니다.
- `refactor`: 기존 코드를 리팩터링하거나 수정할 때 사용합니다.
- `chore`: 중요도가 낮은 수정에 사용합니다.

### 커밋 컨벤션

- 태그는 반드시 소문자로 작성합니다.
- 내용은 한글로 작성합니다.
- 제목은 50자를 넘지 않도록 간단한 명령조로 작성합니다.
- 추가 설명이 필요한 경우 description에 작성합니다.

```text
[feat] 프로젝트 생성 기능 구현
```

### 브랜치 컨벤션

브랜치 이름은 `태그/#이슈번호-작업하는 파일` 형식으로 작성합니다.

```text
feat/#1-projectUI
```

### 브랜치 전략

- `main`: 출시(release)에 사용하는 브랜치입니다.
- `develop`: 개발된 기능들을 최종적으로 합쳐서 확인하는 기본 브랜치입니다.
  - 개발을 마친 후에는 반드시 `develop`에 머지합니다.
  - 개인 브랜치에서 작업을 마치면 개인 브랜치에 `develop`을 먼저 머지한 후, `develop`을 대상으로 Pull Request를 요청합니다.
- `feature`: 태그를 붙이는 모든 작업 브랜치를 의미합니다. 기능 개발, 버그 수정 등은 반드시 해당 작업 브랜치에서 진행합니다.
