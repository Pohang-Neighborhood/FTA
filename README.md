# FTA — Football Tactics Architect

실제 선수 능력치를 바탕으로 사용자가 지정한 이동 경로와 패스 상황을 재현하는 웹 기반 축구 전술 시뮬레이터입니다.

FTA는 승률, 득점, 경기 결과를 예측하지 않습니다. 특정 선수를 어느 위치로 어떻게 움직일지 지시했을 때 그 경로를 그대로 따르게 하고, 지시받지 않은 우리 팀 선수와 상대 팀이 공의 위치와 소유권에 맞춰 어떻게 반응하는지 결정론적으로 계산합니다.

## 현재 구현

- 2026 월드컵 48개 국가, 1,248명 실제 선수 데이터 연결
- `4-3-3`, `4-2-3-1`, `3-4-2-1`, `4-4-2` 포메이션 전환
- 실제 포지션과 능력치에 따른 양 팀 선발 11명 자동 구성
- 항상 표시되는 축약 선수 이름과 선택·포커스 시 전체 이름 표시
- `전술 그리기`에서 선수 드래그 한 번으로 이동·볼 운반·패스 지시 생성
- `시작 배치`에서 선수와 공의 초기 위치·소유권을 별도로 조정
- 경로 지점의 직접 이동·삽입·삭제와 전술 편집 Undo/Redo
- 한 장면을 여러 전술 시퀀스로 나누고, 시퀀스별 waypoint 경로와 동시 액션 지정
- 앞 시퀀스 완료 상태를 다음 시퀀스 시작 위치로 잇는 연속 실행
- 시퀀스 순서와 시퀀스 내부 상대 시각을 이용한 행동 순서 지정
- 지시받지 않은 우리 팀 선수의 지원·압박·커버·블록 자동 경로
- 상대 팀 11명의 공 위치·소유권 기반 자동 반응
- 초기 공 소유자와 경기장 선수 토큰을 이용한 패스 대상 지정
- 이동 충돌·무소유 볼 운반 취소와 패스 수신·차단·미완료·루즈볼 회수 처리
- 50ms 고정 물리 tick과 250ms 자동 전술 판단 주기를 분리하고, 동일 입력에 동일 결과를 보장하는 결정론적 계산
- 재생, 일시정지, 다시 재생, 초기화, 타임라인 탐색
- 선수별 이동 거리·ETA·최근접 간격과 팀별 폭·깊이·평균 간격 변화
- 데스크톱, 태블릿, 모바일 반응형 레이아웃과 키보드 포커스

## 조작 방법

1. 우리 팀과 상대 팀 국가 및 포메이션을 선택합니다.
2. 기본 `전술 그리기` 모드에서 우리 팀 선수를 목표 지점까지 바로 드래그합니다. 공 소유자는 볼 운반, 비소유자는 이동으로 즉시 저장됩니다.
3. 공 소유 선수를 동료 선수 위로 드래그해 놓으면 볼 운반 대신 패스로 인식해 즉시 저장합니다. 세부 액션 버튼과 키보드 입력은 보조 입력 방식으로 계속 사용할 수 있습니다.
4. 시작 위치를 바꿀 때만 `시작 배치`로 전환합니다. 양 팀 선수와 공을 드래그하거나 방향키로 조정하며, 공을 선수 가까이에 놓으면 해당 선수가 소유하고 빈 공간에 놓으면 루즈볼로 시작합니다.
5. 만들어진 이동선을 선택하면 경로 지점을 직접 드래그하고, 구간의 `+`로 지점을 삽입하거나 Delete로 삭제할 수 있습니다. 새 경로를 세밀하게 만들 때는 빈 경기장을 연속으로 드래그합니다.
6. `편집 취소`·`다시 실행` 또는 Command/Control+Z·Shift+Command/Control+Z로 시퀀스 편집을 복구합니다.
7. `전술 시퀀스`에서 액션을 추가할 시퀀스를 선택합니다. 같은 시퀀스의 액션은 시퀀스가 실제로 시작한 시점을 기준으로 실행되며, 기본값 0초는 동시 실행을 뜻합니다.
8. `시퀀스 추가`로 다음 행동 묶음을 만들고 위·아래 버튼으로 실행 순서를 정합니다. 예를 들어 시퀀스 1에 `A→B 패스`와 `D 전진`, 시퀀스 2에 `C 중앙 침투`와 `E 측면 침투`를 넣습니다. 별도의 시작 시각은 입력하지 않습니다.
9. 편집 중에는 선택한 시퀀스가 시작하는 실제 선수·공 위치와 해당 시퀀스의 경로만 경기장에 표시됩니다. 이동선이나 패스선을 직접 선택하면 기존 지시를 편집하거나 삭제할 수 있습니다.
10. `재생`을 누르면 현재 시퀀스의 모든 사용자 지시가 성공·실패·취소 중 하나로 끝난 틱에 다음 시퀀스를 시작합니다. 다음 시퀀스는 직전 완료 순간의 선수·공 위치를 그대로 이어받으며, 자동 반응은 완료 조건에 포함되지 않습니다.
11. 일시정지 상태에서는 타임라인을 움직여 원하는 시점의 위치, 공 상태, 간격과 대형을 확인할 수 있습니다. 지시를 수정하면 기존 계산과 재생 위치는 폐기되고 0초부터 다시 계산합니다.
12. `재생 초기화`는 재생 위치만 되돌리고, `지시 전체 초기화`는 선수·공 시작 배치와 모든 시퀀스 액션을 지웁니다.

## 기술 구성

- React 19
- TypeScript 5
- Next.js 호환 `vinext` 런타임
- Vite 8
- Cloudflare Worker 호환 빌드
- 순수 JavaScript 결정론적 시뮬레이션 엔진
- 인증, 유료 API, 외부 데이터 키 미사용

## 선수 데이터

2026 FIFA 월드컵 선수 명단, PlayerElo 및 시뮬레이션용 세부 능력치 데이터베이스의 구조·생성·검증 방법은 [`data/README.md`](data/README.md)를 참고합니다.

시뮬레이터는 직접 연결된 능력치와 추정된 능력치를 동일한 선수 정보로 사용하며 UI에 별도 배지를 붙이지 않습니다. 추정 능력치가 적용된 선수 목록과 생성 기준은 [`docs/inferred-player-abilities.md`](docs/inferred-player-abilities.md)에 별도로 정리되어 있습니다.

브라우저에는 시뮬레이션에 필요한 선수 식별자, 국가, 이름, 등번호, 포지션, 나이, 소속팀, 능력치만 전달합니다. 데이터 출처, 추정 여부, 주발, 보조 포지션은 클라이언트 데이터와 UI에서 제외합니다.

## 프로젝트 구조

```text
app/
├── SimulationWorkspace.tsx # 시뮬레이터 UI와 재생 상태
├── formations.ts           # 포메이션과 초기 좌표
├── simulator-types.ts      # 클라이언트 안전 선수 타입
├── globals.css             # 반응형 UI와 경기장 표현
└── page.tsx                # 실제 데이터 투영과 서비스 진입
lib/
├── instruction-model.js    # 시퀀스·지시 정렬, 편집, 버전 호환 직렬화 모델
├── player-catalog.js       # 선수 투영과 선발 구성
├── simulation-core.js      # 결정론적 이동·공·패스 엔진
└── tactics-core.js         # 좌표와 포메이션 기초 계산
tests/
├── instruction-model.test.mjs # 시퀀스·지시 순서와 직렬화 호환 테스트
├── player-catalog.test.mjs # 실제 데이터 투영과 선발 테스트
├── simulation-core.test.mjs # 엔진 행동과 결정성 테스트
└── rendered-html.test.mjs   # 빌드 산출물 및 SSR smoke 테스트
```

## 로컬 실행

### 요구사항

- Node.js `>=22.13.0`
- npm

### 설치 및 실행

```bash
npm install
npm run dev
```

개발 서버가 시작되면 [http://localhost:3000](http://localhost:3000)에서 확인할 수 있습니다.

## 검증

```bash
npm run lint
npm run typecheck
npm test
```

전체 검증은 다음 명령으로 한 번에 실행합니다.

```bash
npm run verify
```

## Git 전략

### 태그 컨벤션

- `init`: 가장 처음 Initial Commit에 태그를 붙일 때 사용합니다.
- `feat`: 새로운 기능을 구현할 때 사용합니다.
- `fix`: 버그나 오류를 해결할 때 사용합니다.
- `docs`: README, 템플릿 등 프로젝트 내 문서를 수정할 때 사용합니다.
- `setting`: 프로젝트 관련 설정을 변경할 때 사용합니다.
- `add`: 사진 등 에셋이나 라이브러리를 추가할 때 사용합니다.
- `refactor`: 기존 코드를 리팩터링하거나 수정할 때 사용합니다.
- `chore`: 중요도가 낮은 수정에 사용합니다.

### 커밋 컨벤션

- 태그는 반드시 소문자로 작성합니다.
- 내용은 한글로 작성합니다.
- 제목은 50자를 넘지 않도록 간단한 명령조로 작성합니다.
- 추가 설명이 필요한 경우 description에 작성합니다.

```text
[feat] 프로젝트 생성 기능 구현
```

### 브랜치 컨벤션

브랜치 이름은 `태그/#이슈번호-작업하는 파일` 형식으로 작성합니다.

```text
feat/#1-projectUI
```

### 브랜치 전략

- `main`: 출시(release)에 사용하는 브랜치입니다.
- `develop`: 개발된 기능들을 최종적으로 합쳐서 확인하는 기본 브랜치입니다.
  - 개발을 마친 후에는 반드시 `develop`에 머지합니다.
  - 개인 브랜치에서 작업을 마치면 개인 브랜치에 `develop`을 먼저 머지한 후, `develop`을 대상으로 Pull Request를 요청합니다.
- `feature`: 태그를 붙이는 모든 작업 브랜치를 의미합니다. 기능 개발, 버그 수정 등은 반드시 해당 작업 브랜치에서 진행합니다.
